# SignLearn AI dataset pipeline

This milestone defines a versioned, JSON Lines (JSONL) format for annotated
signing samples and exports consented, approved samples to a CPU-friendly
NumPy archive. It does not recognize signs or claim model accuracy.

## Sample schema (version 1)

Each UTF-8 JSONL line is one sample with these fields:

| Field | Meaning |
| --- | --- |
| `schema_version` | Integer `1`; change this when the record format changes. |
| `sample_id` | Stable UUID for this recording sample. |
| `language_code` | Lowercase project language code, for example `isl` for Indian Sign Language. |
| `signer_id` | Opaque UUID generated by the trusted backend for signer-level splits. Never accept this value from an untrusted client. |
| `consent` | Explicit recording/training consent. |
| `annotation_status` | `pending`, `approved`, or `rejected`; set by the trusted annotation workflow. |
| `created_at` | ISO 8601 timestamp that includes a timezone. |
| `glosses` | Ordered non-empty gloss sequence. |
| `frames` | Ordered frames with strictly increasing `timestamp_ms` and landmark groups. |
| `source_video_key` | Optional relative key of a private Storage object; never a public or signed URL. |

Each frame requires `left_hand`, `right_hand`, `body_pose`, and `face`; each is
either `null` or an array of `[x, y, z]` finite numbers. A hand has exactly 21
landmarks. Pose and face arrays are retained for future models, with upper bounds
to reject unexpectedly large records. Coordinates are kept as emitted by the
landmark extractor; this pipeline does not silently rescale or center them.

Example (one frame shown):

```json
{
  "schema_version": 1,
  "sample_id": "d4f554f1-a0ae-41e6-b9da-8ec2e50ee7f7",
  "language_code": "isl",
  "signer_id": "6f3a8993-0895-45d2-8b62-786837ef4c49",
  "consent": true,
  "annotation_status": "approved",
  "created_at": "2026-10-29T04:30:00Z",
  "glosses": ["HELLO"],
  "frames": [
    {
      "timestamp_ms": 0,
      "left_hand": null,
      "right_hand": null,
      "body_pose": null,
      "face": null
    }
  ]
}
```

In production, the backend must derive the signer UUID and annotation status
from trusted records, enforce authorization and consent, and keep source videos
in a private object-storage bucket. Do not put videos or access URLs in the NPZ
training archive. Use signer IDs to prevent samples from one signer leaking
across training and evaluation splits.

## Export

Save validated, annotated sample records as JSONL, then run:

```powershell
python -m ml.preprocess data\manifest.jsonl data\hand_dataset.npz
```

The output directory must already exist. The compressed NPZ has:

- `features`: `float32`, shape `(total_frames, 2, 21, 3)`, ordered left then right.
- `hand_observed`: `bool`, shape `(total_frames, 2)`, distinguishing a missing
  hand from real landmarks at zero coordinates.
- `offsets`: `int64`, one start offset per sample plus a final end offset.
- `sample_ids`, `signer_ids`, `language_codes`, `gloss_sequences`: Unicode arrays
  aligned with the sample dimension (gloss sequences are JSON strings).
- `schema_version`: scalar-array version for the archive format.

Only records with `consent: true` and `annotation_status: "approved"` are
exported. Other valid records are counted and skipped. If no eligible samples
exist, export fails instead of producing an empty training dataset.

## Exact training archive contract

The trainer reads the preprocessor's NPZ directly with object-pickling disabled.
It requires exactly these arrays; training does not reshape or silently convert
an archive:

| Array | Shape | Dtype | Meaning |
| --- | --- | --- | --- |
| `schema_version` | `(1,)` | `int16` | Dataset/preprocessing schema version, currently `1`. |
| `features` | `(total_frames, 2, 21, 3)` | `float32` | Left-hand then right-hand coordinates, concatenated sample by sample. |
| `hand_observed` | `(total_frames, 2)` | `bool` | Whether each hand was detected for each frame. |
| `offsets` | `(sample_count + 1,)` | `int64` | Frame start/end boundaries; starts at 0, ends at total frames, and increases strictly. |
| `sample_ids` | `(sample_count,)` | Unicode | Unique recording sample identifiers, aligned with offsets. |
| `signer_ids` | `(sample_count,)` | Unicode | Trusted opaque signer identifiers, aligned with samples. |
| `language_codes` | `(sample_count,)` | Unicode | Language code per sample. |
| `gloss_sequences` | `(sample_count,)` | Unicode | Each item is a compact JSON array of ordered gloss strings, for example `["HELLO","THANKS"]`. |

Unobserved hand feature slots must contain zeros. The separate observation mask
is also passed into the model, so zero coordinates for a missing hand are not
interpreted as evidence that the physical hand was at the origin. The model
flattens the 126 coordinates and appends the two observed/missing indicators per
frame.

The NPZ contract has a preprocessing `schema_version`, but does not embed an
identity for a particular dataset build. To preserve the existing NPZ format,
the loader computes a streaming SHA-256 fingerprint of the archive file.
`dataset_version` in split manifests and checkpoints is `sha256:<hex digest>`;
`preprocessing_schema_version` remains the NPZ's integer schema version (`1`).
Thus modified/rebuilt NPZ files cannot silently reuse stale split manifests.
The schema is not changed by splitting or training. Gloss IDs are sorted
deterministically from training-split labels only: ID `0` is CTC blank and gloss
IDs start at `1`. This deliberately avoids learning vocabulary from validation
or test annotations. Training or validation glosses not present in the training
vocabulary cause a clear error; test references with unseen glosses are reported
as unsupported by that checkpoint.

## Signer-independent splitting

At least three distinct signers are required: one or more signers in each of
train, validation, and test. Fewer signers cannot support the requested
independent evaluation, so splitting fails. Signers—not frames or recordings—
are shuffled with the supplied seed and assigned to splits. Samples from a
signer always stay together. The default fractions are 70%/15%/15%, with at
least one signer in each split; small datasets will consequently have coarse
split proportions. Manifests record seed, fractions, dataset version, signer
IDs, and sample IDs. The loader checks that manifests form a full sample
partition with no signer leakage.

```powershell
python -m ml.splitting data\hand_dataset.npz data\splits --seed 42
```

Very small signer counts do not support reliable signer-independent estimates.
The splitter warns below 10 total signers; evaluation warns below 10 test
samples and below 3 test signers.


## Training on a real, prepared dataset

Training automatically selects CUDA if available, otherwise CPU. It uses a
one-layer bidirectional LSTM with frame-level logits and CTC loss. Target glosses
are not frame-aligned; CTC sums over valid monotonic alignments. Repeated
adjacent glosses require an intervening blank frame. The trainer checks the
minimum required input length before optimization and identifies the failing
sample if an alignment is impossible. Padding lengths and target lengths are
passed explicitly.

```powershell
python -m ml.training.train `
  --dataset data\hand_dataset.npz `
  --splits data\splits `
  --output-dir ml\artifacts\isl-baseline `
  --epochs 20 `
  --batch-size 8 `
  --learning-rate 0.001 `
  --hidden-size 64 `
  --seed 42
```

Reduce batch size and hidden size for a low-memory CPU run. The best checkpoint
is selected using validation CTC loss only. The test split is not used for
training, vocabulary creation, or checkpoint selection. Output includes
`best_model.pt` (safely loadable state dictionary and metadata),
`vocabulary.json`, and `training_history.json`. Checkpoint metadata records the
model configuration, vocabulary, dataset/preprocessing versions, training
settings, best epoch, and best validation loss.

## Held-out evaluation

Evaluation loads only the `test` manifest for predictions and reports split
sample/signer counts plus missing-hand statistics. Keep the test split out of
model selection and hyperparameter tuning.

```powershell
python -m ml.evaluation `
  --dataset data\hand_dataset.npz `
  --splits data\splits `
  --checkpoint ml\artifacts\isl-baseline\best_model.pt `
  --output ml\artifacts\isl-baseline\test_report.json
```

Gloss token error rate is Levenshtein edits over gloss tokens (one complete
gloss string is one token) divided by the number of reference gloss tokens.
Character error rate is character-level Levenshtein distance over reference and
hypothesis sequences joined with a single space. Exact-match accuracy counts a
sample correct only when its whole gloss sequence matches. Per-gloss
precision/recall/F1 is omitted for glosses with fewer than five reference
occurrences. These are sequence-level gloss metrics, not frame accuracy and not
proof of arbitrary ISL translation. Small or signer-poor test sets are
explicitly warned about and cannot support reliable generalization claims.

## Isolated letter and digit image classifier

The `archive\isl_dataset` directory is a separate image-classification dataset:
one class-named folder per label and image files named `<label>_<index>.jpg`.
It is not the input format for the temporal BiLSTM-CTC pipeline above. The
image classifier predicts one label from one RGB image; it does not recognize
continuous signing, motion-based letters, words, or translations.

The current dataset scan found 36 folders (`0`-`9`, `A`-`Z`) with 1,000
300-by-300 RGB JPEGs per folder (36,000 total); the images decoded successfully.
Exact byte-identical duplicates exist. The loader excludes hidden folders such
as `.ipynb_checkpoints`, fingerprints image contents, splits each class by
contiguous numeric filename order (70% train, 15% validation, 15% test), and
keeps exact duplicate images in the earliest split. This is intended to reduce
nearby-frame and exact-duplicate leakage; it is not a signer-independent or
recording-independent split. No signer IDs, recording IDs, source, or license
were present in the inspected folder. The images' ISL authenticity, label
semantics, collection consent, and redistribution rights have not been
independently verified. Do not treat the reported image metrics as ISL
recognition-quality evidence.

Install the requirements if they are not already installed, then train from
the repository root in Windows PowerShell:

```powershell
python -m pip install -r ml\requirements.txt
python -m ml.training.train_image_classifier `
  --dataset archive\isl_dataset `
  --epochs 5 `
  --batch-size 32 `
  --image-size 64 `
  --seed 42 `
  --output ml\artifacts\static_classifier
```

Training automatically selects CUDA when available and otherwise uses CPU;
`--num-workers 0` is the Windows-friendly default. The best checkpoint is
selected by validation loss. The test split is evaluated once after checkpoint
selection and is never used for optimization or model selection. Outputs are
`best_checkpoint.pt` (state dictionary and primitive metadata, loadable with
PyTorch `weights_only=True`), `history.json`, `evaluation.json`, and
`split_manifest.json`. The checkpoint contains the deterministic class mapping,
dataset fingerprint, image preprocessing contract, and training settings.
Generated artifacts are ignored by Git.

cannot load this image checkpoint. The separate image endpoint

when configured with `SIGNLEARN_IMAGE_CHECKPOINT_PATH`. The image model predicts
one class per still image. It does not recognize motion, continuous signing,
words, or translation.
